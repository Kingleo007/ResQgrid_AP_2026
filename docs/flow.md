# ResQGrid — How the Codebase Works

A full-stack disaster response app built for learning.
Stack: **React** (frontend) + **Express** (backend) + **Prisma 7** + **PostgreSQL** (database).

---

## Big Picture

```
Browser
  │
  │  Opens localhost:5173
  ▼
Frontend (Vite + React)          ← you see this
  │
  │  fetch('/api/...', { credentials: 'include' })
  │  Vite proxies /api/* → localhost:4000
  ▼
Backend (Express)                ← handles logic
  │
  │  Prisma client
  ▼
PostgreSQL Database              ← stores data
```

The browser talks only to the frontend server (5173).
The frontend talks to the backend (4000) via the Vite proxy.
The backend talks to PostgreSQL via Prisma.

## Frontend — How it Works

### Entry Point

```
main.jsx  →  App.jsx  →  Routes
```

`main.jsx` renders the whole React app inside `<BrowserRouter>` so React Router can read the URL.

`App.jsx` defines which component shows for which URL:

```
/login              → LoginPage
/                   → redirect to /dashboard
/dashboard          → DashboardPage       (inside AppShell)
/incidents          → IncidentsPage       (inside AppShell)
/incidents/new      → NewIncidentPage     (inside AppShell)
/incidents/:id      → IncidentDetailPage  (inside AppShell)
/users/new          → NewUserPage         (inside AppShell)
/403                → AccessDenied        (inside AppShell)
*                   → NotFound
```

### AppShell

Every page except Login is wrapped in `AppShell`, which renders:

```
┌──────────────┬────────────────────────────────┐
│              │  TopBar (breadcrumbs + logout)  │
│   Sidebar    ├────────────────────────────────┤
│  (nav links) │                                │
│              │   <Outlet />  ← page goes here │
│              │                                │
└──────────────┴────────────────────────────────┘
```

`<Outlet />` is a React Router placeholder — it renders whichever page matches the current URL.

### How Pages Fetch Data

Every page uses the same pattern — `useState` + `useEffect` + `fetch`:

```js
// 1. Declare state
const [incidents, setIncidents] = useState([]);

// 2. Fetch when page loads
useEffect(() => {
  fetch('/api/incidents', { credentials: 'include' })
    .then(res => res.json())
    .then(data => setIncidents(data));
}, []);

// 3. Render the data
return <div>{incidents.map(i => <p>{i.title}</p>)}</div>
```

`credentials: 'include'` — tells the browser to send the cookie with every request (needed for auth).

If the backend returns `401` (not logged in), the page does `window.location.href = '/login'`.

### Auth Flow (Frontend Side)

```
LoginPage fills form
  → POST /api/auth/login  { email, password }
  → Backend returns 200 + sets httpOnly cookie
  → navigate('/dashboard')

On any page:
  → fetch('/api/anything', { credentials: 'include' })
  → Cookie is sent automatically
  → If 401 → window.location.href = '/login'

Logout button:
  → POST /api/auth/logout
  → Backend clears the cookie
  → window.location.href = '/login'
```

## Backend — How it Works

### Request Lifecycle

Every API request goes through this exact chain:

```
Request arrives at Express
       │
       ├─ helmet()         adds security headers
       ├─ cors()           allows frontend origin + cookies
       ├─ express.json()   parses JSON body
       ├─ cookieParser()   parses cookies (so we can read req.cookies.token)
       ├─ requestLogger()  logs method + path + status to console
       │
       ├─ Route match (e.g. POST /api/auth/login)
       │
       ├─ validate(schema)     [optional] — Zod checks the request body shape
       ├─ authenticate()       [optional] — checks JWT cookie, sets req.user
       │
       ├─ Controller function
       │     reads req.body / req.params
       │     calls model function
       │     returns res.json(...)
       │
       └─ errorHandler()   catches any thrown errors, sends JSON error response
```

### Auth Flow (Backend Side)

**Login:**
```
POST /api/auth/login  { email, password }
  → authController.login
    → userModel.findByEmail(email)       find user in DB
    → bcrypt.compare(password, hash)     check password
    → jwt.sign({ id, email, name })      create token
    → res.cookie('token', token, { httpOnly: true })   set cookie
    → res.json({ user: { ... } })        return user info
```

**Protected routes:**
```
GET /api/incidents   (cookie: token=xxxx)
  → authenticate middleware
    → reads req.cookies.token
    → jwt.verify(token, JWT_SECRET)      check signature + expiry
    → req.user = { id, email, name }     attach user to request
    → next()                             continue to controller
```

**Logout:**
```
POST /api/auth/logout
  → res.clearCookie('token')   browser deletes the cookie
  → res.json({ message: 'ok' })
```

### Controllers

Thin layer — just reads input and calls the model:

```js
export async function list(req, res, next) {
  try {
    const incidents = await incidentModel.listAll();  // ask model for data
    return res.json(incidents);                        // send to frontend
  } catch (err) {
    next(err);  // pass errors to errorHandler
  }
}
```

### Models

Where all the actual database queries live (using Prisma):

```js
// incidentModel.js

export async function listAll() {
  const rows = await prisma.incident.findMany({
    orderBy: { createdAt: 'desc' },
  });
  return rows.map(toShape);  // convert Prisma object → plain JS object
}
```

`toShape()` converts Prisma's camelCase output to exactly what the frontend expects.

### Validators (Zod)

Before a request reaches the controller, Zod checks the body shape:

```js
// If POST /api/incidents body is missing 'title':
// → 400 Bad Request  { error: { code: 'VALIDATION_ERROR', details: [...] } }
// Controller never runs.
```

## Database — The Two Tables

### `users` table

Stores admin accounts. Passwords are **never** stored plain — only bcrypt hashes.

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key, auto-generated |
| name | text | Display name |
| email | text | Unique — used to log in |
| password_hash | text | bcrypt hash of the password |
| created_at | timestamp | Auto-set on insert |

### `incidents` table

The core data of the app.

| Column | Type | Notes |
|---|---|---|
| id | UUID | Primary key |
| incident_code | text | Unique code e.g. `INC-2026-0001` |
| title | text | Short description |
| hazard_type | text | flood / fire / cyclone / earthquake / landslide / other |
| severity | text | low / moderate / high / critical |
| status | text | reported → active → contained → resolved → closed |
| description | text | Optional longer description |
| location_name | text | Optional place name |
| created_at | timestamp | Auto-set |
| updated_at | timestamp | Auto-updated by Prisma on every save |

## How bcrypt Works (the password part)

```
Signup / Seed:
  plain password "Admin1234!"
        ↓
  bcrypt.hash("Admin1234!", 10)
        ↓
  "$2b$10$..."   ← stored in DB

Login:
  user types "Admin1234!"
        ↓
  bcrypt.compare("Admin1234!", "$2b$10$...")
        ↓
  true / false
```

bcrypt is a one-way hash — you can never reverse it back to the plain password. Even if the database is stolen, the passwords are safe.

---

## How JWT Works (the session part)

```
Login success:
  jwt.sign({ id, email, name }, JWT_SECRET, { expiresIn: '8h' })
        ↓
  "eyJhbGci..."  ← token (3 parts separated by dots)
        ↓
  Set as httpOnly cookie named "token"

Every request:
  Browser sends cookie automatically
        ↓
  jwt.verify(token, JWT_SECRET)
        ↓
  Returns the payload { id, email, name }  or throws if invalid/expired

Logout:
  res.clearCookie('token')  → browser deletes it
```

`httpOnly` = JavaScript cannot read the cookie. Only the browser sends it. This protects against XSS attacks.

## Full Request Example — Creating an Incident

```
1. User fills NewIncidentPage form and clicks "Create Incident"

2. Frontend:
   fetch('/api/incidents', {
     method: 'POST',
     headers: { 'Content-Type': 'application/json' },
     credentials: 'include',          ← sends the cookie
     body: JSON.stringify({
       title: 'Flash flood in Assam',
       hazardType: 'flood',
       severity: 'high',
       locationName: 'Guwahati',
     })
   })

3. Vite proxy → forwards to http://localhost:4000/api/incidents

4. Express receives request:
   → cors() ✓
   → express.json() parses body ✓
   → cookieParser() reads cookie ✓
   → requestLogger() logs it ✓
   → matches POST /api/incidents route

5. validate(createIncidentSchema):
   → Zod checks title, hazardType, severity are present ✓

6. authenticate():
   → reads req.cookies.token
   → jwt.verify() ✓
   → req.user = { id: '...', email: 'admin@...' }

7. incidentController.create():
   → calls incidentModel.createIncident(req.body)

8. incidentModel.createIncident():
   → generates code: INC-2026-0006
   → prisma.incident.create({ data: { ... } })
   → PostgreSQL inserts the row
   → returns the new incident object

9. Controller: res.status(201).json(incident)

10. Frontend receives 201 response:
    → navigate('/incidents')  ← goes back to the list
```

## Full Request Example — Creating a User (with bcrypt)

```
1. Admin opens Sidebar → "Create User" (/users/new)
   Enters Name, Email, and Password (e.g., "secret1234")

2. Frontend:
   fetch('/api/users', {
     method: 'POST',
     headers: { 'Content-Type': 'application/json' },
     credentials: 'include',          ← requires valid login cookie
     body: JSON.stringify({
       name: 'Riya Sharma',
       email: 'riya@resqgrid.local',
       password: 'secret1234'
     })
   })

3. Vite Proxy forwards request to Express at http://localhost:4000/api/users

4. Express Pipeline:
   → cors() checks origin
   → express.json() parses body
   → cookieParser() reads session cookie
   → authenticate middleware verifies token via jwt.verify()
   → validate(createUserSchema) verifies email format and min-8 char password

5. userController.create():
   → Takes plain text password ("secret1234")
   → Calls bcrypt.hash("secret1234", 10)
   → Produces secure hash (e.g. "$2b$10$e8...")
   → Passes { name, email, passwordHash } to userModel.createUser()

6. userModel.createUser():
   → Checks if email already exists (returns 409 if duplicate)
   → Calls prisma.user.create()
   → PostgreSQL stores: { id, name, email, password_hash, created_at }
   → Returns user WITHOUT exposing passwordHash

7. Controller returns 201 Created with safe user JSON

8. Frontend receives 201:
   → navigate('/dashboard')
```

## Environment Variables (backend/.env)

| Variable | What it's for |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `JWT_SECRET` | Secret key for signing/verifying JWTs — keep private |
| `JWT_EXPIRES_IN` | How long a login session lasts (e.g. `8h`) |
| `PORT` | Port the Express server runs on |
| `CLIENT_ORIGIN` | Frontend URL — used for CORS |
| `NODE_ENV` | `development` or `production` |
